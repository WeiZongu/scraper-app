# キーワード検索・抽出ツール

CSSセレクタの指定は不要です。**検索キーワード**でWebを検索し、見つかったページの
テキストをAI（Google Gemini API）が読み取って、**設定した抽出項目（＝表の列）に沿った
レコード**を行として拾い集める、キーワードだけで使えるツールです（ページ内に該当する
情報が無い項目は空欄になります）。
設定（検索キーワード・抽出項目）を
JSONで保存しておき、GUIから選んで実行するだけでデータ収集 → プレビュー（表形式）→
表形式のPowerPointスライド出力まで行えます。

JavaScriptで動的にコンテンツを描画するサイト（SPA等）にも対応するため、
収集エンジンには [Playwright](https://playwright.dev/python/) を使用しています。
Web検索には [Serper.dev](https://serper.dev/) の Search API を使用しています
（検索エンジンのページを直接スクレイピングする方式は、bot検知やHTML構造の変化で
不安定になりやすいため、正式なAPIを使う方式にしています。クレジットカード登録
不要で使い始められるため採用しています）。
ページ内容からの抽出には [Google AI Studio](https://aistudio.google.com/) の
Gemini API を使用しています（意味を理解した抽出ができ、こちらもクレジットカード
登録不要の無料枠で利用できます）。

## 事前準備1: Serper.dev APIキーの取得（クレジットカード不要）

1. https://serper.dev/ にアクセスし、アカウントを作成してログイン
   （執筆時点ではクレジットカード登録不要で、買い切りの無料クレジット2,500回分が
   もらえます。※無料クレジットの内容は変更される場合があるため、登録時の画面で
   最新の内容を確認してください）
2. ダッシュボードでAPIキーを発行し、控えておく
3. このAPIキーを、後述の環境変数 `SERPER_API_KEY` に設定します

## 事前準備2: Gemini APIキーの取得（クレジットカード不要）

1. https://aistudio.google.com/ にアクセスし、Googleアカウントでログイン
   （執筆時点ではクレジットカード登録不要の無料枠があります。※無料枠の内容は
   変更される場合があるため、登録時の画面で最新の内容を確認してください）
2. 「Get API key」（APIキーを作成）からAPIキーを発行し、控えておく
3. このAPIキーを、後述の環境変数 `GEMINI_API_KEY` に設定します

## iPhoneだけで使う（クラウドにデプロイ）

このアプリはPlaywright（ブラウザ自動操作）を使うため、iPhone単体では動作しません。
自分のPCも使わずに済むように、クラウド上に一度だけデプロイしておき、
以降はiPhoneのSafariだけで使う方法です。

- **完全無料・超過時は自動課金されず単に使えなくなる運用にしたい場合** →
  [`ORACLE_DEPLOY.md`](./ORACLE_DEPLOY.md)（Oracle Cloud 永久無料枠、詳細手順あり）
- **多少の月額費用でもよく、手軽さ優先の場合** → 下記のRender手順

### Renderでのデプロイ（参考・有料枠推奨）
無料枠もありますが、スリープや再起動でのデータ消失があり、超過時は自動課金される
アカウント形態です。手軽さ重視ならこちら、課金リスクを避けたい場合は上記Oracle手順を
使ってください。

1. このフォルダの中身をGitHubリポジトリにpush
2. Renderにログイン →「New +」→「Web Service」→ 先ほどのリポジトリを選択
3. **Environment** は「Docker」を選択（同梱の `Dockerfile` が自動で使われます）
4. **Instance Type** は無料枠（Free）でOK
5. 環境変数を設定します:
   - `SERPER_API_KEY`: 上記「事前準備1」で取得したAPIキー（**必須**。無いと検索できません）
   - `GEMINI_API_KEY`: 上記「事前準備2」で取得したAPIキー（**必須**。無いと抽出できません）
   - `APP_PASSWORD`: 好きな文字列（強く推奨）。これを設定しないと、URLを知っている
     誰でもアプリを操作できてしまいます。
6. 「Create Web Service」でデプロイ開始（初回ビルドはブラウザ同梱のため数分かかります）

デプロイが終わると `https://xxxxx.onrender.com` のようなURLが発行されます。
Safariでこれを開き、共有メニュー→「ホーム画面に追加」でアプリのように起動できます。

### 無料枠の制約と対策
- **一定時間アクセスがないとスリープします。** 次回アクセス時に数十秒〜1分ほど起動待ちが発生します。
- **再起動・再デプロイのたびに保存データが消えます（ディスクが一時的なため）。**
  「サイト一覧」タブの **「設定をバックアップ」** で保存済みサイト設定をJSONファイルとしてダウンロードし、
  iPhoneのFilesアプリ等に保管しておいてください。消えてしまった場合は **「設定を復元」** から
  そのJSONファイルを選ぶだけで元に戻せます。
- 出力したPowerPointスライドも同様に一時保存です。生成後はその場でダウンロードして保存してください。
- **無料プランはメモリ512MB程度が上限**です。ブラウザでの画像・フォント読み込みを
  ブロックする、画像処理前に縮小するなどメモリを抑える対策をしていますが、
  それでも一度に開くページ数が多いなどで処理が重くなると
  メモリ超過で実行中に落ちることがあります。発生した場合はRenderの「Events」タブに
  "Out of Memory" 等の表示が出ます。検索範囲を狭める等で軽減できます。

### Render以外の選択肢
[Railway](https://railway.app/) や [Fly.io](https://fly.io/) も同様にDockerfileから無料枠デプロイが可能です。
手順はほぼ同じ（Dockerfileを検出させ、環境変数 `SERPER_API_KEY` と `GEMINI_API_KEY`、
`APP_PASSWORD` を設定するだけ）です。

## 使い方

1. **「検索設定一覧」タブ**の「＋ 新規設定」から新しい設定を作成、または保存済み設定をタップして編集。
2. **「検索設定」タブ**を入力:
   - **設定名**: 一覧に表示される名前（任意の名前でOK）
   - **検索キーワード**: Webを検索するためのキーワード（例: `東京 ラーメン 新宿`）
   - **抽出項目（表の列）**: 「＋ 抽出項目を追加」で行を追加していき、列にしたい
     項目を必要な数だけ登録します。各項目は次の2つの入力欄からなります。
     - **抽出タイトル**: 結果の表・スライドで使われる列名（例: `価格`）
     - **抽出キーワード**: その列で何を探してほしいかをAI（Gemini）に伝える
       説明です。自然言語で構いません（例: `価格` や `出発日`）。`*` とだけ
       書くと、列名から連想される情報があれば自由に埋めるようAIに指示します。
     
     ページのテキストをAIが読み取り、ページ内に含まれる「1件分の情報の
     まとまり」（商品・フライト・店舗情報など）ごとに、登録した抽出項目に
     対応する値を埋めたレコードとして結果の行になります。該当する情報が
     無い項目の列は空欄になります。CSSセレクタの知識は不要です。
     不要になった項目は各行の🗑アイコンで削除できます。
   - **多言語対応（検索キーワードのみ・自動・設定不要）**: 検索キーワードは常に
     日本語・英語・中国語(繁体字)・中国語(簡体字)・韓国語・スペイン語に自動翻訳され、
     日本語以外のページも検索対象になります。翻訳は無料サービス
     （[MyMemory](https://mymemory.translated.net/)）を利用しており、カード登録・
     APIキー登録は不要ですが、無料・非公式に近い性質上、利用状況によっては翻訳が
     失敗することがあります。失敗した場合は自動的に元のキーワードのみで続行します
     （実行ログに成功/失敗が表示されます）。多言語で検索する分、検索回数・処理
     ページ数が単一言語のときより増えるため、Serper.devの無料クレジット消費や
     処理時間もその分増えます。抽出項目（抽出キーワード）は翻訳しません。
     Gemini自身が多言語のページ内容を理解できるためです。
3. 「設定を保存」で検索設定をJSONとして保存（次回以降、「検索設定一覧」タブから呼び出し可能）。
4. **「実行・結果」タブ**で「実行」。検索結果に見つかったページ（最大50件）を片っ端から
   開いてAIに抽出させます。検索 → 各ページを開いて抽出、の様子がログと表形式の
   プレビュー（抽出項目が列、最大200行）に表示されます。
   処理はサーバー側のバックグラウンドで実行されるため、**iPhoneの画面をオフにしたり
   Safariを閉じても、サーバー側では最後まで処理が続きます**。再度アプリを開くと、
   実行中ならその時点までのログが、完了していれば結果がそのまま表示されます
   （ただしRenderの無料プラン自体が長時間無通信でスリープする点は変わらないため、
   あまり長時間放置する場合は注意してください）。
5. 「スライド出力(PowerPoint)」でPowerPointファイルを生成し、表示されたリンクから
   ダウンロードします。出力処理はバックグラウンドで実行され、進捗（何ページ目を
   作成中か等）がバーとログに表示されます（処理中も画面は固まりません）。
   - 構成は 表紙スライド → 表スライド（抽出項目を列とする表、**1ページ5行**、
     6行以上の場合は複数スライドに分割）です。同じ出典ページ由来の行（関連性の
     高いデータ）はなるべく同じスライドにまとまるよう、ページへの割り付けを
     出典単位でグルーピングしてから行っています（1ページの残り行数に収まらない
     場合は、無駄に分断しないよう新しいスライドから始めます）。
   - 表の列は「抽出項目（複数列）＋出典」で、出典列にはページタイトル・
     URL（リンク付き）・動画リンク（あれば）・取得日時をまとめて表示します。
   - セル内のテキストが長い場合は、枠内で折り返して表示されます（はみ出しません）。
   - 各スライドの背景には、そのスライドに含まれる行の画像から作った
     「フルカラースケルトン」（輪郭線部分だけ元画像の色を残した透過画像）を
     敷きます。表のセル自体は不透明な白/薄い青系の背景のため、表の可読性には
     影響しません（画像が無い/取得できない場合は薄いグレーの単色背景になります）。

### 抽出のしくみ（精度について）

CSSセレクタで正確に位置指定する方式や、キーワードの完全一致で拾う方式とは違い、
ページのテキスト全体をAI（Gemini API）に渡し、「登録した抽出項目に対応する情報を
持つレコード（1件分の情報のまとまり。商品・フライト・店舗情報など）をすべて
見つけて構造化データとして返す」よう指示する方式です。表記ゆれや言い回しの違いに
強く、CSSセレクタやキーワードの完全一致に頼る方式より柔軟に情報を拾えますが、
AIによる読み取りのため100%正確な抽出は保証されません。抽出キーワード（AIへの
説明）を具体的にすると精度が上がりやすいです。

ページ内に複数のレコードがあれば、それぞれ別々の行として返されます。ある項目に
該当する情報がそのレコードに無い場合、その列は空欄になります。同じ内容のレコードが
サイト内の複数ページにまたがって重複しないよう、全列の内容が完全に一致するものは
自動的に1件にまとめられます。

さらに、数値部分だけが微妙に異なる重複（例:「営業時間 11:00〜21:00」と
「営業時間 11:00〜22:00」のように、ページごとに表記がわずかにブレている場合）は、
**別々のページから取得した**行同士に限り、数値以外の列がすべて一致するものを
グルーピングした上で、該当する列の数値部分を中央値に置き換えて1件にまとめます。
同じページ内でAIが見つけた複数のレコード（例: 同じページに載っている複数の
フライト候補）は、たとえ数値の桁数などが似ていても平均化されず、それぞれ別の
行として残ります（別々の実在する情報を誤って混ぜないようにするためです）。

画像・動画も、各ページから見つかった代表的なもの（ヘッダー・ナビゲーション・
フッターやロゴ・アイコン類は除く）を1つずつ拾います（PowerPointの表スライドには
埋め込まれませんが、出典列の動画リンクから確認できます）。

## 注意事項

- 対象サイトの利用規約・`robots.txt` を確認し、許可された範囲でご利用ください。
- Web検索には Serper.dev の Search API を利用しています。1回の検索で開くページ数は
  最大50件です（暴走防止と、買い切りクレジットを使いすぎないための上限）。
  無料クレジットを使い切ると検索結果が0件（またはそこまでの結果）で終了します
  （実行ログに表示されます）。
- 抽出はAI（Gemini API）による読み取りベースのため、100%正確な抽出は保証されません。
  抽出キーワード（AIへの説明）を具体的にすることで精度が上がります。
- ブラウザは常にheadless（画面を表示しない）で実行されます。クラウド環境には画面(Xサーバー)が
  無く、headlessをオフにすると必ず失敗するためです。
- スライド出力時に画像をダウンロードして埋め込むため、画像を含む件数が多いほど
  出力に時間がかかります。
- クラウド無料枠にデプロイして公開する場合は、`APP_PASSWORD` 環境変数を必ず設定してください
  （未設定だとURLを知る誰でも操作できてしまいます）。

## ディレクトリ構成

```
scraper_app/
├── main.py                 # Flet GUI 本体（パスワード認証・バックアップ機能含む）
├── Dockerfile               # Render/Railway等へのデプロイ用
├── .dockerignore
├── requirements.txt
├── scraper/
│   ├── config.py            # 検索設定の読み書き
│   ├── engine.py             # 検索・キーワード抽出処理（Playwright）
│   └── exporter.py           # PowerPointスライド出力
├── site_configs/            # 検索設定(JSON)保存先
│   └── sample.json
└── assets/                  # Fletが配信する静的ファイル置き場
    ├── output/               # 出力されたPowerPointファイル（ダウンロードリンクの実体）
    └── downloads/            # 検索設定バックアップJSONの置き場
```
